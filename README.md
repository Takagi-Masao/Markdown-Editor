# Markdown 编辑器 - 实时预览 + 导出 PDF

一个功能丰富的 Web 端 Markdown 编辑器，支持实时预览、代码高亮、数学公式渲染以及 PDF 导出。

## ✨ 主要特性

- **便携式部署**：在线加载各依赖项，基本无需额外下载。
- **实时分屏预览**：左侧编辑，右侧即时渲染 Markdown 效果。编辑区与预览区滚动位置实时同步，体验丝滑流畅。
- **本地文件上传**：支持从本地上传 Markdown 文件（也可直接把 `.md` / `.txt` 文件拖拽到页面打开），自动加载文件内容。
- **代码语法高亮**：自动识别代码语言，使用 highlight.js 进行高亮。
- **LaTeX 数学公式**：支持行内公式 `$...$` 和块级公式 `$$...$$`，由 KaTeX 渲染。
- **多重安全保存机制**：既可保存 Markdown 文件也可以导出 PDF。当前文件有未保存修改时，打开新文件（或拖入新文件）会弹出「保存 / 不保存 / 取消」确认框；刷新或关闭页面使用浏览器原生离开确认（是否显示由浏览器决定）。撤销回到已保存内容后，不再视为未保存修改。
- **会话与草稿恢复**：已保存或刚打开的文件内容、文件名会自动恢复，不弹草稿提示；只有实际未保存的修改才询问恢复，包括删除全部内容后的空草稿。编辑后约 500ms 保存到浏览器本地存储，并在页面隐藏、离开时立即保存。
- **编辑辅助工具**：提供加粗、斜体、行内代码等快捷按钮，支持 `Ctrl+B`、`Ctrl+I` 等快捷键，可在 `main.js` 中的 `handleGlobalKeydown` 自行修改。工具栏插入操作基于 `execCommand('insertText')`，不会破坏浏览器原生的 `Ctrl+Z` 撤销历史。

## 🛠️ 技术栈

- **前端框架**：Vue 3 (Composition API)
- **Markdown 解析**：marked
- **代码高亮**：highlight.js
- **数学公式**：KaTeX
- **PDF 导出**：浏览器原生 `window.print()` 配合 CSS 打印样式
- **UI**：纯 CSS

## 🚀 快速开始

1. 克隆或下载本项目到本地。
2. 使用本地服务器打开 `index.html`，如：
   - 使用 `VS Code Live Server` 插件打开 `index.html`。
   - 在项目根目录使用 Python 内置的 HTTP 服务器打开 `index.html`：

     ```bash
     python -m http.server <port>
     ```

     或者使用 `node.js` 打开：

     ```bash
     npm install -g http-server # 如果没有它就先下载
     http-server -p <port>
     ```

     然后访问 `http://localhost:<port>` 即可。
3. 编辑 Markdown 内容或者本地上传 Markdown 文件，右侧实时预览效果。点击「保存 Markdown」按钮，保存方式按以下顺序选择：
   - Chrome/Edge 等支持 File System Access API 的浏览器，在安全上下文中可原位置写回已关联文件。文件句柄按文档身份保存在 IndexedDB 中，刷新后仍可使用；浏览器可能要求在再次点击保存时授权，不会在恢复页面时申请写入权限。
   - 没有关联句柄时使用浏览器原生“保存”对话框。通过普通文件输入框或拖拽打开的文件没有可写句柄，需要另存为。
   - 不支持该 API 时使用下载回退；未命名的文档先询问文件名。下载请求作为一次导出记录，但浏览器无法确认下载是否真正写入磁盘，完整内容仍保留在恢复会话中，请自行确认下载结果。
   - 保存期间继续编辑不会丢失新内容：保存的是点击时的快照，新修改仍标记为未保存。重叠的保存请求合并为当前保存，完成后再次保存即可写入新修改。若选择“保存后打开”，期间产生的新修改会阻止打开。
   - 取消文件选择、读取或写入失败不会清空原文档及文件关联。权限被拒绝或写入失败时保留内容，请再次点击保存并授权或重试。
4. 点击「导出 PDF」按钮，在弹出的打印对话框中选择「另存为 PDF」即可保存。较长代码块在右侧预览界面会折叠，但在生成 PDF 时完全展开。

## ⚠️ 使用须知
- 导出 pdf 时，本编辑器自带页眉页脚（呈灰色）。
- 刷新会恢复最近的会话，不会因保存后 Live Server 自动刷新而回到欢迎文本。若文件监听器在写入完成回调前触发刷新，恢复内容仍在，但可能保守地提示恢复草稿。
- 恢复数据依赖同一浏览器、同一来源（协议、主机及端口）；清理站点数据、无痕模式限制、存储空间不足或浏览器崩溃可能导致恢复不可用，不能替代磁盘备份。多标签页共用该来源的最近一次会话，不提供跨标签合并。
- 老版本草稿没有已保存基线，无法可靠判断是否已经保存，因此首次恢复仍按未保存修改处理。拒绝恢复时先显示已知的干净基线（未知则显示初始文档），旧草稿保留到下一次编辑、打开或保存；恢复的文件内容不自动检查磁盘上的外部修改。
- 用 Edge/Chrome 等浏览器打开，体验最佳。

## 回归测试

测试不需要安装 npm 依赖，使用 Node.js 22.15+：

```bash
npm run check
npm test
node tests/browser-smoke.mjs
```

`npm test` 覆盖基线比较、空草稿、旧版迁移、快照保存竞争、权限与失败恢复、取消拖入及原子打开。测试使用单进程模式，避免受限环境中的子进程管道限制。

浏览器烟雾测试使用真实 Chrome、原生撤销及 IndexedDB/OPFS 文件句柄，覆盖打开、保存、刷新、恢复、空文档和页面离开持久化。默认查找 Windows 的 Chrome；其他安装路径可用 `CHROME_PATH` 环境变量指定。测试自行使用临时端口及浏览器配置目录，浏览器依赖项仍从页面配置的 CDN 加载，需要网络连接。
